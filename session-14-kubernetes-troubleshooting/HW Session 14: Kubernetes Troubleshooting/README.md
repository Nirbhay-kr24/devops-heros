### kubectl explain

The `kubectl explain` command displays documentation for Kubernetes resources and their available fields. It is useful when creating or modifying YAML manifests.

Example:

```bash
kubectl explain pod
kubectl explain deployment.spec
kubectl explain service.spec
```
### kubectl top
The kubectl top command displays resource usage such as CPU and memory for Pods or Nodes.
Example:
```
kubectl top pods
kubectl top nodes
```

### kubectl get -o wide
The -o wide option provides additional details when listing Kubernetes resources, such as Pod IP addresses and the Node where a Pod is running.
Example:
```
kubectl get pods -o wide
kubectl get nodes -o wide
```

## Kubectl Logs vs Kubectl Events

The main difference between these commands is the type of information they provide. `kubectl logs` focuses on the output produced by an application container, while `kubectl events` shows activity and status changes reported by Kubernetes itself.

### `kubectl logs` (Application Level)

Use `kubectl logs` when you need to inspect what an application inside a container is doing. It is especially useful when an application is running but producing errors or unexpected output.

**Common Examples:**

* `kubectl logs my-app-pod` — Displays the current logs from the Pod.
* `kubectl logs my-app-pod -f` — Continuously follows the application's logs.
* `kubectl logs my-app-pod -p` — Displays logs from the previous container instance, which can be useful after a container crashes.

### `kubectl events` - (Cluster Level)

Use Kubernetes events when investigating problems related to `Pod scheduling`, `image pulling`, `container startup`, or other cluster operations.

**Common Examples:**

* `kubectl get events --sort-by='.metadata.creationTimestamp'` —Lists recent events in chronological order.
* `kubectl describe pod my-app-pod` — Provides detailed information about a specific Pod, including relevant events near the bottom of the output.
